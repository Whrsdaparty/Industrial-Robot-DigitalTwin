# PLCopen TC6 XML 2.01 Schema Coverage

The included `tc6_xml_v201.xsd` contains a broad interchange model for IEC 61131 projects. A graphical engineering environment can represent hundreds of attributes and nested graphical objects. This first application intentionally covers the parts that can be completed reliably through a compact form-based interface.

## Fully supported project areas

The exporter supports the required PLCopen project sequence and validates it against the supplied XSD.

### File header

- Company name and URL
- Exporting product name, version, and release
- Creation timestamp
- Content description

### Content header

- Project name and version
- Modification timestamp
- Organization and author
- Documentation language
- Comment
- Page size
- FBD, LD, and SFC scaling
- Extension declaration through `addDataInfo`

### Data types

- Elementary and derived aliases
- Enumerations
- Structures
- One-dimensional arrays
- Simple initial values
- Documentation

### Variables

- Configuration-global variables
- Resource-global variables
- POU local and temporary variables
- POU input, output, in-out, external, and global variables
- Direct addresses
- Simple initial values
- Constant, retain, nonretain, persistent, and nonpersistent list attributes
- Documentation

### POUs

- Programs
- Function blocks
- Functions and return types
- ST bodies
- Legacy IL bodies
- Empty schema-valid LD, FBD, and SFC bodies
- Preserved source notes for graphical languages
- Documentation

### Instances

- One configuration
- Multiple resources derived from task resource names
- Multiple tasks
- Periodic interval or single-trigger task attributes
- Task priority
- Program instances attached to tasks
- Task documentation

### Project documentation and extension data

- Project documentation
- Siemens S7-1200 hardware extension
- `handleUnknown="preserve"` behavior

## Supported Siemens hardware data

- Manufacturer, family, category, product, article number, and catalog source
- Catalog properties from the embedded brochure data
- Quantity and device tag
- Rack and slot
- PROFINET station name
- IP address, subnet mask, and gateway
- Firmware and hardware version
- Lifecycle status
- Product, datasheet, support, manual, and CAx URLs
- Dimensions and weight
- Operating temperature and approvals
- Website checked date
- Engineering notes

## Not generated by this first application

The application does not generate graphical network geometry and connectivity, including contacts, coils, blocks, connectors, continuation points, rails, jumps, SFC steps, transitions, action blocks, or graphical connection coordinates.

It also does not currently provide forms for:

- Multiple configurations
- Configuration access variables and configuration variables
- Taskless resource-level POU instances
- POU actions and transition declarations
- Multi-dimensional arrays
- Structured and array initial-value editors
- Subrange and pointer type editors
- Global IDs on every eligible element
- Arbitrary vendor elements inside graphical networks

These structures remain valid future extensions. The limitation is in the editor, not in the included XSD or validator.

## Design rule

Do not encode physical rack semantics by misusing PLCopen `configuration` or `resource`. The Siemens hardware model remains in preserved extension data until a separate AutomationML or internal engineering model is implemented.
